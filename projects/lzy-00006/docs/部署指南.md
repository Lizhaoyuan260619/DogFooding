# 实时语音对讲模块 部署指南

## 1. 系统要求

### 1.1 服务器要求

| 配置项 | 最低要求 | 推荐配置 |
|--------|---------|---------|
| 操作系统 | Linux (Ubuntu 18.04+) / Windows Server 2016+ | Ubuntu 22.04 LTS |
| Node.js | 14.x | 18.x LTS |
| 内存 | 2GB | 4GB+ |
| CPU | 2核 | 4核+ |
| 带宽 | 10Mbps | 100Mbps+ |
| 磁盘空间 | 10GB | 50GB+ |

### 1.2 客户端要求

| 平台 | 浏览器要求 |
|------|-----------|
| Windows | Chrome ≥80, Firefox ≥75, Edge ≥80 |
| macOS | Chrome ≥80, Firefox ≥75, Safari ≥14, Edge ≥80 |
| iOS | Safari ≥14, Chrome ≥80 |
| Android | Chrome ≥80, Firefox ≥75 |

## 3. 部署步骤

### 3.1 前置准备

1. **安装 Node.js**
```bash
# Ubuntu/Debian
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt-get install -y nodejs

# CentOS/RHEL
curl -fsSL https://rpm.nodesource.com/setup_18.x | sudo bash -
sudo yum install -y nodejs

# 验证
node --version  # 应输出 v18.x.x
npm --version   # 应输出 9.x.x
```

2. **配置 HTTPS（生产环境必需）**

WebRTC 要求 HTTPS 环境（localhost 除外）。建议使用 Let's Encrypt 免费证书：
```bash
# 安装 certbot
sudo apt-get install certbot

# 获取证书
sudo certbot certonly --standalone -d yourdomain.com
```

### 3.2 代码部署

1. **克隆或上传代码到服务器**
```bash
cd /opt
git clone <your-repo-url> collaborative-whiteboard
cd collaborative-whiteboard
```

2. **安装依赖**
```bash
npm install --production
```

3. **环境变量配置**

创建 `.env` 文件：
```bash
# .env
PORT=3000
NODE_ENV=production

# HTTPS 配置（可选，如使用反向代理可忽略）
# SSL_KEY=/etc/letsencrypt/live/yourdomain.com/privkey.pem
# SSL_CERT=/etc/letsencrypt/live/yourdomain.com/fullchain.pem
```

### 3.3 配置 STUN/TURN 服务器（可选但推荐）

默认使用 Google 的 STUN 服务器。生产环境建议配置自建 TURN 服务器以提高 NAT 穿透成功率：

1. **安装 coturn**
```bash
sudo apt-get install coturn
```

2. **配置 coturn**
```bash
# /etc/turnserver.conf
listening-port=3478
tls-listening-port=5349
listening-ip=<your-server-ip>
external-ip=<your-server-ip>
user=<username>:<password>
realm=yourdomain.com
cert=/etc/letsencrypt/live/yourdomain.com/cert.pem
pkey=/etc/letsencrypt/live/yourdomain.com/privkey.pem
```

3. **修改前端代码配置**

在 `public/js/voice-manager.js` 中修改 `iceServers` 配置：
```javascript
const configuration = {
    iceServers: [
        { urls: 'stun:stun.l.google.com:19302' },
        { urls: 'stun:stun1.l.google.com:19302' },
        {
            urls: 'turn:your-turn-server.com:3478',
            username: '<username>',
            credential: '<password>'
        }
    ],
    // ...
};
```

### 3.4 使用 PM2 启动服务

```bash
# 安装 PM2
npm install -g pm2

# 启动应用
pm2 start server/server.js --name whiteboard

# 设置开机自启
pm2 startup
pm2 save

# 查看状态
pm2 status
pm2 logs whiteboard
```

### 3.5 配置 Nginx 反向代理（推荐）

```nginx
# /etc/nginx/sites-available/whiteboard
server {
    listen 80;
    server_name yourdomain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    # WebSocket 配置
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # 更长的超时时间用于 WebSocket 长连接
    proxy_read_timeout 86400;
    proxy_send_timeout 86400;

    location / {
        proxy_pass http://localhost:3000;
    }

    location /socket.io/ {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

启用配置：
```bash
sudo ln -s /etc/nginx/sites-available/whiteboard /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## 5. 故障排查

### 5.1 常见问题

**问题1：语音连接失败**

可能原因：
- 浏览器未授权麦克风权限
- 防火墙阻止 UDP 端口
- NAT 穿透失败

排查步骤：
1. 检查浏览器控制台是否有权限错误
2. 检查防火墙是否允许 UDP 端口 1024-65535
3. 考虑配置 TURN 服务器

**问题2：语音延迟高或卡顿**

可能原因：
- 网络带宽不足
- 用户网络环境差
- 服务器负载高

排查步骤：
1. 检查服务器 CPU/内存使用率
2. 检查网络带宽使用情况
3. 查看用户网络统计（前端可获取 `getStats()`）

**问题3：听不到声音**

可能原因：
- 系统音量未开启
- 浏览器标签页被静音
- 音频输出设备选择错误

排查步骤：
1. 检查系统音量
2. 右键浏览器标签页，确认"取消静音"
3. 检查浏览器音频输出设备设置

**问题4：麦克风不工作**

可能原因：
- 麦克风被其他应用占用
- 浏览器权限被拒绝
- 麦克风设备故障

排查步骤：
1. 检查系统麦克风设置
2. 检查浏览器权限设置
3. 使用系统录音功能测试麦克风

### 5.2 日志关键字

| 关键字 | 含义 |
|--------|------|
| `voice:join` | 用户加入语音 |
| `voice:leave` | 用户离开语音 |
| `iceConnectionState` | ICE 连接状态变化 |
| `RTCPeerConnection` | WebRTC 连接相关 |
| `NotAllowedError` | 权限被拒绝 |
| `NotFoundError` | 未找到麦克风 |

## 6. 备份与恢复

### 6.1 数据备份

语音模块不存储语音数据，仅需备份：
- SQLite 数据库文件（房间、画板数据）
- 配置文件
- SSL 证书

备份脚本示例：
```bash
#!/bin/bash
# backup.sh

DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/opt/backups/whiteboard"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
cp /opt/collaborative-whiteboard/data.db $BACKUP_DIR/db_$DATE.db

# 备份配置
cp /opt/collaborative-whiteboard/.env $BACKUP_DIR/env_$DATE

# 压缩
tar -czf $BACKUP_DIR/backup_$DATE.tar.gz -C $BACKUP_DIR db_$DATE.db env_$DATE

# 删除旧备份（保留30天）
find $BACKUP_DIR -type f -mtime +30 -delete
```

添加定时任务：
```bash
crontab -e

# 每天凌晨3点备份
0 3 * * * /opt/scripts/backup.sh
```

### 6.2 灾难恢复

1. **恢复代码**
```bash
cd /opt
git clone <your-repo-url> collaborative-whiteboard
cd collaborative-whiteboard
npm install --production
```

2. **恢复数据**
```bash
tar -xzf /opt/backups/whiteboard/backup_<date>.tar.gz
cp db_<date>.db /opt/collaborative-whiteboard/data.db
cp env_<date> /opt/collaborative-whiteboard/.env
```

3. **启动服务**
```bash
pm2 start server/server.js --name whiteboard
```

## 8. 扩展方案

### 8.1 水平扩展

当前架构为单节点，如需支持更多并发用户：

1. **引入 Redis 适配器**
```bash
npm install @socket.io/redis-adapter redis
```

修改 `server/server.js`：
```javascript
const { createAdapter } = require("@socket.io/redis-adapter");
const { createClient } = require("redis");

const pubClient = createClient({ url: "redis://localhost:6379" });
const subClient = pubClient.duplicate();

Promise.all([pubClient.connect(), subClient.connect()]).then(() => {
    io.adapter(createAdapter(pubClient, subClient));
});
```

2. **负载均衡**

使用 Nginx 或 HAProxy 进行多节点负载均衡。

### 8.2 媒体服务器（>10人）

当前 Mesh P2P 架构支持最多 10 人。如需支持更多参与者，可引入 SFU 服务器：

- **Mediasoup** - 高性能 WebRTC SFU
- **Janus** - 通用 WebRTC 服务器
- **LiveKit** - 现代化 WebRTC 基础设施
