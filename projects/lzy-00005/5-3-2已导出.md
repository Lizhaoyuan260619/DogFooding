## 问题 1：悬浮卡片消失逻辑异常

**根本原因**：
- 原代码使用嵌套 `setTimeout` 结构，存在竞态条件
- `hide()` 方法内部判断 `isHoveringCard` 为 true 时直接返回，导致后续无法再触发隐藏
- 事件委托中 `mouseout` + `relatedTarget` 判断不可靠，尤其是 DOM 层级复杂时
- 每次渲染内容时重复绑定 click 事件，没有清理旧监听器

**修复方案**（[link-preview.js](file:///e:/WORKSPACE_ROOT/项目/lzy-00005/static/js/link-preview.js)）：
1. **明确的状态管理**：新增 `isHoveringTrigger`、`isHoveringCard`、`isVisible`、`isAnimating` 四个独立状态标记
2. **分层隐藏逻辑**：
   - `tryHide()`：条件检查入口，仅当两个悬浮状态都为 false 时才执行
   - `hide()`：调度延迟隐藏（200ms）
   - `forceHide()`：强制立即隐藏（用于点击外部、滚动、窗口缩放）
   - `performHide()`：实际执行淡出动画和清理
3. **精确的触发元素追踪**：通过 `currentTriggerEl` 和 `leaveTrigger()` 方法精确标记鼠标是否在触发元素上
4. **事件监听器清理**：渲染内容前先移除旧的 click 监听器，避免内存泄漏和重复触发
5. **改进的事件绑定**（[main.js](file:///e:/WORKSPACE_ROOT/项目/lzy-00005/static/js/main.js#L189-L226)）：重写 `bindPreviewHover`，正确处理 `relatedTarget`，排除子元素间移动产生的冗余事件

## 问题 2：悬浮卡片位置边界处理不稳定

**根本原因**：
- 使用 `position: absolute` + `scrollX/scrollY` 计算，滚动时偏移容易出错
- 仅使用 `cardMaxHeight` 估算高度，未使用实际渲染后的尺寸
- 缺少卡片翻转后顶部/底部超出视口的二次校正
- 定位时机过早（内容加载前定位，内容加载后高度变化导致位置错误）

**修复方案**：
1. **改用 `position: fixed`**（[style.css](file:///e:/WORKSPACE_ROOT/项目/lzy-00005/static/css/style.css#L1190-L1205)）：完全基于视口坐标定位，彻底消除滚动偏移误差
2. **使用实际渲染尺寸**（[link-preview.js](file:///e:/WORKSPACE_ROOT/项目/lzy-00005/static/js/link-preview.js#L321-L360)）：先显示卡片，通过 `getBoundingClientRect()` 获取真实宽高后再定位
3. **完整的边界夹取（clamp）逻辑**：
   - 水平：`left` 始终限制在 `[margin, viewportWidth - cardWidth - margin]`
   - 垂直：根据下方空间自动决定显示在触发元素上方或下方，然后再限制 `top` 在 `[margin, viewportHeight - cardHeight - margin]`
4. **内容加载后二次定位**：缓存命中或 API 返回后重新调用 `positionCard()` 确保位置精确
