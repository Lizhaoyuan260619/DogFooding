**User**

开发一个基于 Node.js 的轻量化命令行加密通信工具，该工具采用纯命令行界面（无 Web 组件），使用本地 SQLite 数据库存储密钥信息、消息记录及联系人数据。工具需实现以下核心功能模块，确保通信内容的机密性、完整性和不可否认性： 
 
 1. 密钥管理系统： 
    - 实现 RSA-2048 位非对称密钥对生成功能，确保密钥强度符合安全标准 
    - 支持 PEM 格式密钥文件的导入与导出，包含公钥和私钥的完整处理流程 
    - 提供密钥对列表展示功能，显示所有本地存储的密钥对及其唯一指纹信息（使用 SHA-256 哈希算法生成密钥指纹） 
    - 确保私钥存储安全，采用密码加密保护机制 
 
 2. 消息加密模块： 
    - 实现混合加密方案：采用 AES-256-CBC 算法加密消息主体，生成随机初始化向量(IV) 
    - 使用接收方 RSA 公钥加密 AES 密钥，确保只有指定接收方能解密 
    - 最终输出 Base64 编码的 JSON 格式加密包文件，包含加密消息、加密的 AES 密钥、IV 和必要元数据 
    - 支持通过联系人昵称或直接指定公钥文件路径两种方式选择接收方公钥 
 
 3. 消息解密模块： 
    - 解析输入的 Base64 编码 JSON 加密包文件 
    - 使用用户提供的 RSA 私钥解密出 AES 密钥 
    - 利用解密得到的 AES 密钥和 IV 解密消息内容，并以明文形式输出 
    - 实现基础错误处理机制，处理密钥不匹配、文件损坏等常见异常情况 
 
 4. 数字签名功能： 
    - 使用发送方私钥对消息内容进行 SHA-256 哈希运算并生成数字签名 
    - 接收方可以使用发送方公钥验证消息签名的真实性和完整性 
    - 将签名信息整合到加密包中，确保消息在传输过程中未被篡改 
 
 5. 安全删除功能： 
    - 实现简化版 shred 命令，对指定文件执行安全删除操作 
    - 采用随机数据对文件内容进行3次覆写，彻底清除原始数据 
    - 确保文件删除后无法通过常规数据恢复软件恢复原始内容 
 
 6. 联系人管理系统： 
    - 基于 SQLite 数据库实现轻量级联系人存储功能，包含联系人昵称和对应公钥文件路径 
    - 提供基础的联系人添加、查询、修改和删除功能 
    - 加密消息时可直接通过联系人昵称选择接收方，无需重复输入公钥文件路径

## 六大核心模块

### 1. 密钥管理系统 ([keys.js](file:///e:/WORKSPACE_ROOT/%E9%A1%B9%E7%9B%AE/lzy-00008/src/keys.js))
- **RSA-2048 密钥对生成**：使用 Node.js `crypto.generateKeyPairSync` 生成
- **PEM 格式导入/导出**：支持公钥和私钥的完整 PEM 文件操作
- **SHA-256 指纹**：对公钥 PEM 内容计算 SHA-256 哈希作为唯一指纹
- **私钥加密存储**：使用 AES-256-CBC + scrypt 密钥派生加密私钥后存入数据库

### 2. 消息加密模块 ([encrypt.js](file:///e:/WORKSPACE_ROOT/%E9%A1%B9%E7%9B%AE/lzy-00008/src/encrypt.js))
- **混合加密方案**：AES-256-CBC 加密消息主体 + RSA-OAEP 加密 AES 密钥
- **随机 IV 生成**：每次加密生成 16 字节随机初始化向量
- **Base64 JSON 输出**：加密包包含 `encrypted_message`、`encrypted_aes_key`、`iv`、`signature`、`sender_fingerprint`
- **双模式选收件人**：支持联系人昵称或公钥文件路径

### 3. 消息解密模块 ([decrypt.js](file:///e:/WORKSPACE_ROOT/%E9%A1%B9%E7%9B%AE/lzy-00008/src/decrypt.js))
- **完整解密流程**：Base64 解码 → JSON 解析 → RSA 解密 AES 密钥 → AES 解密消息
- **Buffer 正确拼接**：使用 `Buffer.concat` 避免多字节 UTF-8 字符在块间分裂导致乱码
- **错误处理**：密钥不匹配、文件损坏、格式错误等异常均给出明确提示

### 4. 数字签名功能 ([sign.js](file:///e:/WORKSPACE_ROOT/%E9%A1%B9%E7%9B%AE/lzy-00008/src/sign.js))
- **RSA-SHA256 签名**：使用发送方私钥对消息进行 SHA-256 哈希后签名
- **签名验证**：使用发送方公钥验证签名真实性与完整性
- **签名整合**：签名自动嵌入加密包中，解密时一并验证

### 5. 安全删除功能 ([shred.js](file:///e:/WORKSPACE_ROOT/%E9%A1%B9%E7%9B%AE/lzy-00008/src/shred.js))
- **3 次随机覆写**：使用 `crypto.randomBytes` 生成随机数据覆盖文件内容
- **fsync 刷盘**：每次覆写后调用 `fs.fsyncSync` 确保数据写入磁盘
- **最终删除**：覆写完成后调用 `fs.unlinkSync` 删除文件

### 6. 联系人管理系统 ([contacts.js](file:///e:/WORKSPACE_ROOT/%E9%A1%B9%E7%9B%AE/lzy-00008/src/contacts.js))
- **SQLite 存储**：存储昵称和公钥文件路径，唯一性约束
- **完整 CRUD**：添加、查询、修改、删除联系人
- **密钥验证**：添加联系人时自动验证公钥文件有效性

## CLI 命令速查

```bash
# 初始化数据库
node src/index.js init

# 密钥管理
node src/index.js keys generate -n <名称>          # 生成 RSA-2048 密钥对
node src/index.js keys list                         # 列出所有密钥对
node src/index.js keys export-pub -n <名称> -o <路径>  # 导出公钥
node src/index.js keys export-priv -n <名称> -o <路径> # 导出私钥
node src/index.js keys import -n <名称> --pubkey <路径> --privkey <路径>  # 导入密钥对
node src/index.js keys delete -n <名称>             # 删除密钥对

# 联系人管理
node src/index.js contacts add -n <昵称> -k <公钥路径>
node src/index.js contacts list
node src/index.js contacts update -n <昵称> --new-nickname <新昵称>
node src/index.js contacts delete -n <昵称>

# 消息加密/解密
node src/index.js encrypt -m <消息> -r <收件人> -s <发送方密钥名> -o <输出路径>
node src/index.js decrypt -i <加密文件> -k <解密密钥名> -s <发送方密钥名>

# 数字签名
node src/index.js sign -m <消息> -k <密钥名> -o <输出路径>
node src/index.js verify -m <消息> -s <签名> -k <公钥路径>
node src/index.js verify -f <签名文件> -k <公钥路径>

# 安全删除
node src/index.js shred -f <文件路径>
```
